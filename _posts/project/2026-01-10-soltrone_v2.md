Soltrone is a quadrotor built as a platform for onboard perception and, later, multi-robot experiments. The first version was too small to carry the companion computer, cameras, and battery those experiments need: adding sensors and flight time requires larger motors and batteries, which in turn require a larger frame. Version 2 is the redesign. This post covers Phase 1, the airframe build and first flight, and doubles as a component guide for building a similar drone.

## Development History: Soltrone v1

Version 1 was a small frame with a Raspberry Pi 5 as the companion computer and a Speedbee F4 Plus flight controller. It never flew a full mission, but it settled most of the design decisions for v2.

- **Firmware.** Betaflight was sufficient for basic flight but limited for companion-computer work. Migrating to ArduPilot gave richer MAVLink and companion-computer support, and a stable phone ↔ Raspberry Pi ↔ flight controller link through a web dashboard served on the Pi.
- **Board support.** ArduPilot support for the Speedbee F4 Plus is poor: a target for a similar board produced repeated "config error, fix problem and reboot" messages, and the generic `OMNIBUSF4` target was what finally ran. Arming checks for sensors the board lacks were disabled in the Full Parameter List.
- **Power.** The Pi 5 browned out under load until it was fed by a 5 A UBEC. Two ESCs were lost to solder bridges and vibration-induced shorts before every joint was re-soldered, heat-shrunk, and continuity-tested.
- **Safety.** An indoor test with the web controller ended with a propeller damaged by motor heat. After that, the test protocol became: bench test with propellers removed, tethered hover, then outdoor flight, with a throttle limit, a geofence, and link-loss disarm.

## Essential Components

Every multirotor needs the following:

- **FC (Flight Controller)**
- **ESC** (two options: 4-in-1 or individual ESCs)
- **Motors**
- **Propellers**
- **Battery**
- **Drone frame**
- **Receiver + RC controller**

Camera and GPS are optional and depend on the mission.

---

## Component Selection Guide

### Flight Controller (FC)

The choice depends on the intended use:

- **Mission drone** → ArduPilot + Mission Planner
- **FPV racing** → Betaflight

Each FC has specialized software for calibration and settings. ArduPilot provides more universal firmware support.

### ESC (Electronic Speed Controller)

There is a trade-off here. Bigger drones require stronger batteries and more powerful motors, which need better ESCs to handle the load safely.

- **Small drone** → 4-in-1 ESC (compact, simpler wiring)
- **Large drone** → Individual ESCs (better for electrical safety and heat dissipation)

### Motors

Buying motors and ESCs from the same brand as a set is recommended. Motors often have ESCs designed for them, and matching them reduces compatibility issues.

### Propellers

For a drone to hover stably, diagonal motors must spin in the same direction. One pair spins CW (clockwise), the other CCW (counter-clockwise). Each motor type requires matching props:

- CW motor → CW prop
- CCW motor → CCW prop

Mismatched propellers will flip the drone on takeoff.

### Battery

Battery selection depends on the motor and ESC specifications. Match the voltage (e.g., 4S, 6S) and ensure the discharge rate (C rating) can handle the motors' current draw.

### Drone Frame

Frames are standardized by the prop size they can accommodate (e.g., 5-inch, 7-inch). Choose a frame that fits the motors and props.

### Receiver + RC Controller

For an autonomous drone the transmitter is used only for hover tests and as a failsafe, so an inexpensive one is sufficient. A receiver is still required.

## Next Steps

Phase 1 is complete. The next step is to mount three stereo cameras (front-left, front-right, and rear) and run the [Semantic VSLAM]({% post_url project/2025-12-30-semantic_vslam %}) pipeline, already tested in Unreal Engine 5, on the physical drone. The longer-term goal is to use the drone as one member of a heterogeneous multi-robot team; a quadrotor is a good first platform because it moves in three axes and is comparatively cheap to build.
